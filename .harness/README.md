# .harness

This folder records how this repository's agent harness was set up. The harness was generated by [harness](https://github.com/AndyLan0503/powerharnessing11k), a setup tool that **only the repo's maintainers run**. Everyone else just clones and pulls as usual.

## Collaborators: nothing to install

Everything the harness needs is committed to this repo. Claude Code picks it up automatically:

- `CLAUDE.md`: how agents work here
- `.claude/settings.json`: permissions and hook wiring
- `.claude/hooks/`: guardrail and quality hooks (plain bash; `jq` speeds them up but isn't required)
- `.claude/skills/`, `.claude/agents/`: repo workflows and subagents

See what agents did on your machine (the log is local and git-ignored):

```sh
.harness/report.sh            # all time
.harness/report.sh --days 7
```

**Want a guardrail or permission changed?** Open a PR that edits `.harness/config` or `.harness/permissions` and describes why, or open an issue. A maintainer regenerates the harness on that branch. Please don't hand-edit generated files: the next regeneration keeps your edit but stops updating that file.

## Maintainers

| File | Purpose |
|---|---|
| `config` | Setup answers: stack, commands, modules, guard level, owners |
| `permissions` | Extra Claude Code permission rules (`allow\|ask\|deny <rule>`), merged into `.claude/settings.json` |
| `manifest` | Checksums of generated files; lets updates skip files people have edited. Don't edit. |
| `report.sh` | Local audit-log summary |

To apply a change, or to pick up a newer harness (nothing goes on your PATH):

```sh
git clone --depth=1 https://github.com/AndyLan0503/powerharnessing11k ~/.harness-workflow   # once; later: git -C ~/.harness-workflow pull
~/.harness-workflow/setup.sh update      # re-apply .harness/config (run from this repo)
~/.harness-workflow/setup.sh doctor      # check for drift
~/.harness-workflow/setup.sh             # re-run the setup wizard
```

Commit the result like any other change. Edited files are never overwritten; harness writes `<file>.harness-new` next to them for you to merge.
